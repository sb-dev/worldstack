# Worldstack specifications

These six documents are the canonical design specifications. Canonical authority does not mean the specified behaviour is implemented or accepted.

| Specification | Owns | Authority |
|---|---|---|
| [01 — System and boundaries](01-worldstack-system-and-boundaries.md) | Purpose, knowledge integrity, ownership and non-goals | Canonical |
| [02 — World model and integration](02-world-model-and-system-integration.md) | Model contracts, provenance, fidelity, time and cross-system boundaries | Canonical |
| [03 — Experimentation and evidence](03-experimentation-evidence-and-emergence.md) | Experiment identity, replay, determinism and investigation | Canonical |
| [04 — Game and representation](04-game-world-and-representation.md) | Permanent test games, state/representation separation and fidelity ladders | Canonical |
| [05 — Production Skills and Pactwright](05-production-skills-and-pactwright-integration.md) | Specialist composition, external dependencies and knowledge ownership | Canonical |
| [06 — Repository and development](06-repository-and-development-process.md) | Bootstrap adoption, correction, capability maturity and abstraction rules | Canonical |

The [founding research log](../research-logs/2026-09-06-worldstack-real-world-systems-experimentation-and-emergence.md) supplies research context and open questions. It is not a competing implementation contract. [Roadmaps](../roadmaps/README.md) sequence the work; [bootstrap Intents](../../specs/graph/README.md) carry the delivery acceptance targets until canonical Pactwright adoption.
